# Northpass Native v0.4: Northpass Split

Northpass Split is original C++20 code for a controlled segmentation experiment, not a demonstrated ISP bypass. Flowseal remains the only consumer connection engine. Neither the UI, `IDpiEngine` native adapter nor the authenticated broker accepts Split profiles or arbitrary arguments. Ordinary native pass-through behavior is unchanged.

## Framing and state

`parse_client_hello` checks a complete single TLS handshake record (maximum 16,384 record bytes), exact ClientHello handshake length, legacy version, bounded session ID, even nonempty cipher list, null compression, exact extension lengths and at most 64 distinct extension types. Extension contents are opaque, not decoded into hostnames. No credentials, TLS keys, hostnames or payload history are retained. This is structural framing validation, not TLS authentication or complete extension-semantic validation.

Split requires observed SYN, matching SYN-ACK and ACK state in the existing bounded flow tracker. The candidate must start exactly at client ISN+1 and acknowledge server ISN+1. The first complete ClientHello is split into nine payload bytes followed by ordered chunks bounded by configured MTU (1280..1500, laboratory uses 1280). Modulo-2^32 sequence progression is tested. IPv4 and IPv6 without extension headers are supported; no IP options, fragments, URG/FIN/RST/SYN/ECN data flags, TCP authentication/SACK/unknown options or TLS stream reconstruction are attempted. Only EOL/NOP/timestamp TCP options have reviewed copy semantics. Unsupported/partial/reordered packets and unknown state are forwarded unchanged. A full same-sequence retransmission produces the same segments; a partial retransmission is forwarded unchanged. No payload is retained to correlate later traffic.

IP lengths and IPv4 identifiers, TCP sequence numbers, final-segment PSH and IPv4/TCP checksums are generated independently of offload bytes. Known nonzero invalid checksums and unsupported observations are refused. Windows loopback can omit zero IPv4/TCP checksum fields even when its metadata indicates validity. Only exact outbound loopback lab inputs normalize those absent fields in a temporary validation copy, preserve/check every nonzero original checksum and report OffloadUnverified. Original bytes/metadata are never changed by observation. Every generated segment has independently calculated and validated checksums. Synthetic cases cover this exception, non-loopback refusal, timestamp headers, wrapping sequence numbers, many sizes and both IP versions. Raw v0.3 checksum observation counters can still record the omitted loopback fields as arithmetic mismatches; that is not proof of corrupted destination traffic. MTU here is a conservative configured bound, not discovered path MTU.

## Versioned transaction

ABI 3 byte-replacement transactions remain compatible. ABI 4 `SegmentTransaction` permits only the typed `TcpSegmentation` capability in Synthetic or Laboratory scope; Live is refused. It owns an immutable bounded original, permits 2..16 segments and validates every segment against a canonical packet derived from the original. Headers, addresses/ports, ACK/window/options, sequences, checksums, byte-for-byte payload coverage, ordering, no gaps/overlaps and MTU are checked before commit. Candidate packets become available for transmission only after validation/commit. Strategy initialization and shutdown are explicit and strictly validated.

Before any send attempt, rejection/allocation/observation errors fall back to the exact original. A commit alone does not transmit. `record_sent` validates ordered successful sends. After any ambiguous send failure or first successful send, rollback is forbidden. Neither the engine nor the tests promise a network transaction: sending one segment and failing the next can leave an incomplete ClientHello, trigger retransmission or interrupt the connection. The worker reports send failures, stops and drains captured originals rather than automatically resending the original of a partly transmitted transaction. Cancellation before transmission uses original forwarding; cancellation after a send starts completes the bounded proposal unless a send fails. Kernel losses remain unknown.

## Authorized lab gate

Only the explicit owned command-line test path accepts `--test-capability --lab-split --lab-seconds N`, with TCP loopback mode, a single reserved port 49152..65535, direct live parent and stdin STOP. N must be 1..20; the deadline cannot be extended or auto-recovered. IPC/broker mode, idle mode, missing consent flags, non-TCP scope and unrelated fault switches are refused. There is no profile, persisted enable setting, automatic activation or arbitrary filter/remote address option. Packet-level guards additionally require outbound non-impostor loopback packets with exact 127.0.0.1 or ::1 endpoints. Only client-destination traffic to the lab server port is transformed. SYN/ACK and server traffic remain unchanged. A privileged local caller is outside the broker threat boundary; use only dedicated sockets you own.

`NativeSplitLabWindowsTests` creates its own short-lived self-signed TLS endpoint. The client pins that exact certificate; no Windows certificate store, global network or security settings are changed. Schannel does not accept ephemeral key handles, so the test imports its generated PFX into a temporary current-user key container without PersistKeySet; certificate disposal deletes that key and temporary PFX bytes are zeroed. Baseline and Split sessions use actual SslStream TLS 1.2/1.3 and fixed public test patterns, not browsing traffic. Three independent connections per session exchange 1, 4096 and 32768 bytes in both directions and compare exact destination reconstruction.

The primary WinDivert handle captures originals. A separate lower-priority sniff-only/receive-only handle captures actual post-injection packets in the same isolated scope, with an explicit 128-packet/256-KiB/500-ms queue bound. Trace files contain only sequence/ACK, length, flags, checksum fields/observation state and framing booleans; no payloads, SNI or credentials. Logging caps at 256 post-packet records and the first 64 accepted proposals (at most 16 segments each); numeric observation counts can be larger. Tests compare committed send sequences/lengths with actual sniff observations. Prepared segments must have valid canonical checksums. Windows loopback can strip checksum fields after injection too: post-capture accepts independently valid checksums or explicitly unverified absent fields, never nonzero invalid checksums. It does not report stripped fields as verified. This is an OS loopback trace, not an external wire capture or proof of hardware wire checksums. No packet-capture service or persistent driver service is configured.

The toy packet-local DPI simulator recognizes a complete ClientHello contained in one packet and misses the split pieces; their exact reassembly still validates. This fixture intentionally lacks TCP stream reassembly. Its result is not evidence about Russian DPI, Flowseal effectiveness or any production middlebox.

## Metrics and evidence

`NORTHPASS_SPLIT_METRICS protocol=4` reports proposed/accepted/rejected transformations, successful lab send calls, send failures, known incomplete-original forwarding, unknown kernel losses, actual sniff count and proposal/validation latency. `NorthpassSplitMetrics` provides strict typed internal diagnostics; it explicitly keeps reconstruction unknown. Only the destination harness can record successful reconstruction. Existing native metrics separately report CPU, private memory, queue pressure and processing latency. Captured/forwarded counts use original captured-packet units, not generated wire-segment counts. Known-drop counters are a lower bound/report of originals not fully reinjected, not an exact wire/kernel loss census. A failed send can have ambiguous delivery.

Synthetic performance output is labeled SYNTHETIC and kept separate from real TLS lab wall time, CPU/memory, latency and trace measurements. No hardware throughput, losslessness or race-freedom claim follows from these short tests.

## Run and interpret

- Linux: `bash scripts/setup-native-cloud.sh` (39 CTest groups, ASan/UBSan).
- Windows elevated dedicated CI/test machine: `./scripts/build-native.ps1`, then locked restore and `dotnet test tests/Northpass.Windows.Tests/Northpass.Windows.Tests.csproj -c Release --filter FullyQualifiedName~NativeSplitLabWindowsTests --logger trx --results-directory TestResults`.
- `lab-tls-results.json`, `lab-*-trace.txt` and `engine-native-split-faults.txt` are actual lab evidence. The Git revision in packaged manifests identifies the tested build.
- Main CI also retains real broker identity/replay/substitution, queue saturation, driver reopen, worker crash/parent ownership, WPF/localization, offline installer repair and uninstall acceptance. Windows Server 2022 adds an actual second OS lab. These runner OSs do not certify desktop Windows 10/11.
- Real fault cases suppress the first or second captured lab segment, assert nonzero worker exit and no claimed rollback, then reopen the actual driver. TLS may recover via normal retransmission after interception stops, or fail; both outcomes are recorded. STOP during authenticated TLS application traffic checks reconstruction after cleanup. The one-second hard-deadline case checks that TLS works after automatic driver cleanup.

See [manual desktop acceptance](NATIVE_V04_MANUAL.md). Interactive UAC and real affected-ISP effectiveness remain manual/unverified. There has been no independent security review. Future work should evaluate full retransmission/network-loss behavior and external lab capture, review this broker/strategy boundary independently, and add desktop/hardware validation before considering any broader interception.
