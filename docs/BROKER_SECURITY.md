# Privileged broker security boundary

The desktop host owns a random exclusive local named pipe, held worker PID/creation time and file leases. Windows elevation starts a fixed protected native bootstrap through `ShellExecute`/`runas`. Cancellation error 1223 becomes a retryable permission-declined error; access/driver/setup failures remain distinct. There are no shell commands, external binary paths, arbitrary BAT execution or downloaded authorization catalogs in this protocol.

The bootstrap validates its direct Program Files application location, protected ownership/ACLs and absence of links, checks every managed worker file against compiled SHA-256/size entries and holds read-only, non-delete leases **before CLR startup**. It creates the worker suspended in a kill-on-close job and supplies only SystemRoot, WINDIR and System32 PATH. User CLR startup hooks, profilers, DOTNET settings and DLL path overrides cannot execute in the privileged managed worker before its checks. The UI separately verifies the complete helper directory against its embedded immutable manifest before requesting elevation. Trusted installer preparation seals the application before launch.

The medium-integrity UI is pipe server; privileged worker is client. DACL allows SYSTEM/Administrators and the owning user with a mask excluding pipe-instance creation; mandatory medium label and remote-client rejection are set. The server uses first-instance exclusivity and max one instance. Both sides query kernel peer PIDs, fixed image paths, creation time, user SID, authentication LUID and session. UI also verifies the worker is the direct child of its owned bootstrap. A fresh 256-bit challenge travels only on this verified local channel. No secret is exposed in command lines, environment, files or logs. Another same-user process may attempt connection, but cannot impersonate the verified owned worker. Windows process injection into an already authorized desktop host is outside this boundary.

Version 3 messages have exact command/engine/strategy allowlists, monotonic sequence numbers, unknown/duplicate JSON field rejection, bounded depth/frame/payload deadlines and typed argument validation. Replayed/out-of-order commands terminate the privileged session. A reviewed strategy ID plus validated ports and normalized data-only list content is reconstructed inside the worker; medium-user paths/raw command lines never become privileged input. Native scope remains idle/dedicated loopback only. Inline lists are bounded (four slots, 1 MiB each); temporary copies/snapshots are protected and cleaned up.

Disconnect, owner death and shutdown cancel operations and gracefully stop owned engine children. Bootstrap job closure kills orphan children after worker crashes. A ten-second owner-death deadline is a last-resort cleanup bound, not a lossless guarantee. The medium UI cannot kill unrelated elevated processes and retains/reports ownership when cleanup times out. No driver-wide uninstall or global network/security changes occur.

Current authorization deliberately accepts **same-account split-token UAC** only. Alternate administrator credentials with a different user/logon are rejected; standard-account credential elevation needs a separately reviewed authorization design. App installation must be a protected direct child of Program Files; developer/user-writable copies cannot use the broker. Local administrators and SYSTEM are trusted. Driver/kernel losses remain unknown, regardless of user-mode counters.

Acceptance uses a real restricted medium token and actual published WPF/native/driver components. The pre-elevated CI handoff replaces only interactive UAC approval and is explicitly not proof of secure-desktop approval/denial. Error-code mapping tests are also not UAC interaction. Clean Windows 10/11 tests must still cover approval, denial, alternate credentials, low/remote hostile peers, signed distribution, repair/uninstall under normal desktop sessions and hardware network pressure. Do not switch production composition until the real medium/privileged broker acceptance gate passes.
