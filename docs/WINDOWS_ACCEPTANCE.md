# Windows acceptance checklist (required before a release)

These checks are **not implied** by a Linux build or portable tests. Run on a clean Windows 11 x64 machine and record the Windows version, engine Git revision/hash, exact strategy, outcomes and logs. Do not mark checks passed without executing them.

1. Install .NET SDK 8.0.425, run `scripts/test.ps1`, then `scripts/build.ps1`. Verify both test suites executed with nonzero test counts. Run the self-contained EXE without requiring a separately installed .NET runtime on the target machine.
2. Open the WPF UI, resize to its minimum dimensions and a large display, navigate all five pages and use keyboard focus. Change `en`/`ru`/`az` in Settings, save and restart. Editor/technical messages currently remain English.
3. Confirm an empty draft cannot start. Try malformed JSON, a duplicate Id, a nonexistent binary, missing dependencies, a missing Lua/list/blob reference, an unknown option and a rejected Zapret1 option. Verify a readable error and no interception process.
4. Test automatic first-launch component preparation with no extra confirmation or download. Exercise the custom Repair confirmation with keyboard acceptance/cancellation. Verify offline setup with networking disabled and subsequent reuse without downloading. Confirm archive/component hash rejection, missing/quarantined file errors, safe extraction and rejection of writable ACLs/extra DLLs. Verify the installed pinned revision and use a provider-tested strategy for that exact version. Confirm `--version` and `--dry-run` output, then connect. Check the real `winws2.exe` PID and stdout/stderr in Diagnostics. A dry run does not validate Lua behavior.
5. Click Connect repeatedly and attempt changes during startup: one owned interception process only. Disconnect and confirm that process and its descendants terminate. Connect again and verify a new session starts. Change strategies only after disconnection and confirm the previous process is gone.
6. End the owned engine in Task Manager. Confirm Error and actual exit code, without a Protected/bypass claim. Enable recovery, reconnect and induce failures: at most three attempts per session. Disconnect/exit during recovery and confirm no later restart. Verify manual reconnection resets the budget.
7. Use Diagnostics to test a known HTTPS URL with the engine disconnected, then active. Record actual HTTP outcome and timings. A successful response establishes that URL's reachability only; it does not establish provider-wide bypass. Test a timeout/unreachable host and confirm a failure result, not a success badge.
8. Minimize with tray preference on/off. Use tray Show, Connect/Disconnect and Exit. Exiting must stop the owned engine and remove the tray icon. Start a second app instance and verify it does not create another engine. Closing the main window exits rather than hiding.
9. Add/edit/export/import a strategy; duplicate imports must preserve the original. Restart and verify profile selection/settings. Corrupt settings.json and confirm it is preserved and saving is blocked with a useful error. Restore a backup to continue. Check references after importing JSON because assets are not copied.
10. Publish to a stable location, enable Windows autostart and save. Verify Task Scheduler's `Northpass-<user SID>` task and user/elevation/quoted EXE path. Log out/in: the app starts in tray without connecting automatically. Disable autostart and verify task removal. Test with paths containing spaces.
11. Enable update checks and save, then restart. Confirm application metadata and the installed-vs-reviewed engine check, no unreviewed release execution/download, and useful handling of absent releases or network failure. Export logs, verify meaningful diagnostics and review paths/hosts before sharing.
12. Test an optional reviewed engine update: inject an acquisition/probe failure and ensure the old verified revision remains selected; then test a successful update and rollback, tampered rollback rejection and blocked updates during a session. Build the Inno Setup installer with `scripts/build.ps1 -Installer`. Install/launch/uninstall on clean Windows x64. Verify reviewed offline engine payload, full notices and corresponding source archives are bundled; local settings remain; the current user's autostart task is removed. Verify default install permissions and elevation. Sign and authenticate release artifacts before public distribution.

If any criterion fails, fix the defect and rerun the affected checks. A source PR or CI artifact is not a statement that Northpass 0.4 is a release-ready or universally working bypass application.

For v0.4 also evaluate custom chrome, dropdowns, keyboard focus, EN/RU/AZ wrapping, 100/150/200% DPI, text scaling, small-window scroll behavior, actual installer post-install launch/UAC, and full About licence/source access. CI screenshots and published bootstrap checks are evidence for the runner only.
